# NovaOS architecture decision record

Status: accepted for milestones M1–M2. Decisions marked *provisional* will be revisited at the stated
milestone. This replaces the earlier Debian/Chromium appliance (now in `docs/legacy/`).

| # | Topic | Decision | Why |
|---|---|---|---|
| 1 | Language and toolchain | C11 plus GNU-syntax assembly, built with **clang/lld 18** as a freestanding cross toolchain (`--target=x86_64-unknown-none-elf`, later `aarch64-unknown-none-elf`). No libc, no compiler runtime. | One compiler targets x86-64 and ARM64 with no separate cross toolchain to build. It is easy to install on Ubuntu, Debian and WSL2. *Provisional:* Rust for new drivers is possible later. |
| 2 | Kernel design | A **small monolithic kernel** for M1–M3: drivers that must handle interrupts live in the kernel. Policy (what to start, what each program may do) lives in userspace `init`. Drivers sit behind narrow C interfaces so they can move to userspace driver processes from M4. | Fastest route to a working, testable system. User-mode drivers need IPC and DMA isolation (an IOMMU, or a bounce-buffer design) that do not exist yet. |
| 3 | Boot protocol | **Multiboot2**, loaded by GRUB 2 for x86-64 (BIOS and UEFI from one hybrid ISO). ARM64 (M5): the kernel will be a raw `Image` with a Linux-compatible arm64 boot header, so QEMU `-kernel` and U-Boot/EDK2 can load it, with the device tree passed in `x0`. | GRUB is an allowed, established bootloader. It provides the memory map and a linear framebuffer on both firmware types. |
| 4 | Memory | A bitmap physical allocator (4 KiB pages) over the bootloader's memory map. The kernel identity-maps RAM below 1 GiB and the 2–4 GiB device window with **supervisor-only** 2 MiB pages. Each process gets its own PML4, and **1–2 GiB is the private user region**, mapped with 4 KiB pages. NX is enabled, and W^X is enforced by the ELF loader. | Simple and auditable. A higher-half kernel and more than 1 GiB of RAM come in M2. |
| 5 | Processes and scheduling | Processes have one thread each (threads come in M3). Scheduling is **preemptive round-robin** on the 8254 timer (250 Hz, 20 ms slice), with task 0 as the idle loop. Blocking states: sleep and wait. A process killed by a CPU exception exits with `0x100 \| vector`. | Enough for the shell, recovery and tests. Priorities and SMP are not designed yet. |
| 6 | Syscall ABI | `int $0x80`, number in `rax`, arguments in `rdi/rsi/rdx`, negative error codes. The ABI is defined in `include/nova/abi.h`. Every pointer is checked against the caller's page tables (`user_range_ok`), and sizes are bounded. | Easy to trace and test. `syscall/sysret` is an optimisation for later. |
| 7 | Access control | **Capabilities** are granted at spawn time (`CAP_DISPLAY`, `CAP_INPUT`, `CAP_SPAWN`, `CAP_POWER`). A child can only receive a subset of its parent's capabilities. Device memory is mapped into a process only through a capability-checked syscall. User mode has no I/O-port access (no IOPB). | Explicit device permissions without a full object-capability kernel yet. |
| 8 | IPC | *Not implemented yet (M2).* Plan: synchronous message passing over kernel-owned endpoints (fixed 64-byte messages plus shared-memory grants for bulk data). The display server, storage service and network service will use it. | Needed before services can move out of the kernel. |
| 9 | Executables | **ELF64**, static, ET_EXEC, linked at `0x40000000`. Every header field is validated before use. Programs are embedded in the kernel image until a filesystem exists. | Standard and easy to inspect with existing tools. |
| 10 | Userspace runtime | `libs/libnova`: crt0, syscall wrappers and string helpers. There is no POSIX layer. Linux binaries, Chromium and Go's runtime **cannot run** on NovaOS; any of them would need a port. | Honest scope. |
| 11 | Storage (M2) | A virtio-blk driver plus **NovaFS**: a copy-on-write, checksummed log of records with an atomic superblock flip. Separate read-only system images are planned for A/B slots. | Crash safety without fsck. Power-loss tests use QEMU kill-at-random. |
| 12 | Graphics and input | M1 uses the **bootloader framebuffer** with a software renderer (`libs/gfx`), integer only. The shell draws into its own back buffer and copies to the mapped framebuffer. Keyboard events come through a kernel queue to the `CAP_INPUT` holder. Planned: a compositor process (M3) with per-app surfaces in shared memory, and virtio-gpu (M3). | Gets the real UI on screen first. |
| 13 | Theme | `theme/tokens.json` holds values copied from `ui/reference/ui.html`. `theme/tools/gen-assets.mjs` rasterises fonts, icons and wallpaper at build time into `theme/generated/` (committed). The shell, recovery and the kernel panic screen all link the same generated theme. | One source of truth for the design. No browser at runtime. |
| 14 | Networking (M4) | virtio-net driver, then a NovaOS stack: Ethernet, ARP, IPv4, ICMP, UDP, TCP, DHCP and a DNS stub resolver. IPv6 and TLS are tracked separately. TLS will use an established library (BearSSL or Mbed TLS) and no custom cryptography. | |
| 15 | Recovery | Nova Recovery is a **separate program** in the same signed system image, started by a separate boot entry or by `init` after three shell failures. It needs no writable data. A text fallback runs on serial when there is no display. Later there will be a separate recovery image slot (see RECOVERY.md). | Recovery stays independent of the shell. |
| 16 | Updates (M4) | Update packages signed with **Ed25519** (an established library, e.g. Monocypher, verified against published test vectors), installed to the inactive A/B slot, with boot counting and rollback. | Authenticated, atomic updates. |
| 17 | Portability | `arch/<arch>/arch.h` defines the trap frame, syscall register accessors and the RAM window. `arch/<arch>/` provides entry, exceptions, page tables (`as_*`), `arch_switch_to` and `arch_user_frame`. `drivers/<platform>/` provides the console, timer, input, RTC and power. `kernel/` has no architecture code. User programs are the same C sources built per architecture; only `USER_BASE` differs (x86-64 1 GiB, AArch64 512 GiB). | Done in 0.3 (M5); both ports pass the same tests. |
| 18 | ARM64 boot (QEMU virt) | The kernel ELF is loaded by QEMU `-kernel` at 0x40200000 and runs at EL1 (it drops from EL2 if started there). There is no device-tree parser yet: the virt machine's fixed addresses are used, the RAM size comes from fw_cfg and the boot mode from the fw_cfg file `opt/nova/cmdline`. The display is `ramfb` (fw_cfg DMA). Input is virtio-input over modern virtio-mmio. Power is PSCI over HVC. | Smallest working path. A DTB parser is needed before real ARM hardware (phone). |
